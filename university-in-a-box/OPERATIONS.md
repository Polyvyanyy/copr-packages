# Эксплуатация японского продукта

## Статус запуска

В репозитории реализованы аккаунты, серверное сохранение, 7-дневный trial без карты, интеграция подписки $20 USD / месяц, поддержка и шаблоны развёртывания. **Это не подтверждение готового публичного бизнеса.** Реальный оператор не назначен, юридическая и независимая предметная проверки не завершены, рабочие ключи и полный цикл реальной оплаты и доставки писем не подтверждены. До приёма пользователей и денег оператор должен закрыть критерии в конце документа.

Открытые учебные материалы доступны для чтения без оплаты. Платная услуга — размещённое хранение и синхронизация, а не снятие ограничений авторского права. Завершение trial или подписки не закрывает тексты и не отменяет права по их лицензиям.

## Архитектура и границы

Один Node.js-процесс обслуживает API и интерфейс с одного origin. В разработке он подключает middleware Vite с HMR, в production — проверенную сборку `dist/`. Better Auth отвечает за пароли, сессии, подтверждение адреса, восстановление и отзыв сессий. SQLite работает в WAL-режиме с внешними ключами и миграциями. Платёжные данные карт остаются у Stripe; доставка сервисных писем подключается через Resend.

Это **одноузловая** архитектура: постоянный локальный диск, один экземпляр приложения и резервные копии. Не запускайте несколько реплик с разными SQLite-файлами, не кладите WAL-базу на сетевой файловый диск и не используйте эфемерный serverless-диск. Для горизонтального масштабирования нужна отдельная миграция на общую транзакционную БД. Высокая доступность и конкретная пропускная способность не заявлены без нагрузочного испытания.

В runtime нет LLM, поэтому расход на токены равен $0. Это не означает нулевую себестоимость: остаются хостинг, резервные копии, письма, эквайринг, поддержка и предметная редактура.

## Локальная разработка

```sh
cd university-in-a-box
npm ci
npm run dev -- --host 0.0.0.0 --port 3000
```

Требование `package.json`: Node.js `^24.15.0 || >=26.0.0`. Эффективные команды Hoplite хранятся в `../.hoplite/settings.json`; Preview запускает тот же dev-сервер с API.

`.env` для разработки не обязателен. Если он существует в текущем каталоге, сервер и операционный CLI читают его через `process.loadEnvFile`. Не копируйте незаполненный production-шаблон для обычного локального запуска. Локальная база и автоматически созданный секрет находятся в закрытом каталоге `server/data/`, исключённом из Git. Письма разработки сохраняются в `server/data/mail/` (либо `APP_DATA_DIR/mail/`), а не отправляются наружу, не выводятся в консоль и не выдаются через публичный API. Журнал содержит приватные одноразовые ссылки: не публикуйте его. Это реальные локальные аккаунты; development разрешает вход до подтверждения почты, production — нет. Никогда не используйте здесь production-данные.

Допущены только origins из явного списка доверия, включая настроенный development Preview. Не добавляйте `*` и не доверяйте произвольному заголовку `Host`. В production публичный origin задаётся через `APP_URL`. Смена домена, схемы или порта требует проверки allowlist, ссылок в письмах и обратных переходов оплаты; проверка origin в API и в аутентификации должна оставаться согласованной.

```sh
npm run test          # все тесты
npm run test:server   # только server/
npm run build         # tsc --noEmit && vite build
npm run check         # npm run test && npm run build
npm run format:check  # prettier --check .
```

## Подготовка production

1. Подготовьте постоянный сервер с поддерживаемым Node.js (предпочтительно ветка 24 LTS), TLS-домен, отдельного системного пользователя и каталог `/var/lib/japanese` с правами `0700`.
2. Выполните `npm ci`, `npm run check` и `npm run format:check` в каталоге приложения. Зависимости закреплены lockfile; скрипты сборки нативных зависимостей разрешены адресно, а не глобальным обходом проверок.
3. Скопируйте **только структуру** `.env.example` в защищённый `/etc/japanese/environment` (`0600`). Впишите реальные реквизиты оператора, адрес поддержки, URL и версию принятых условий, настройки почты и отдельный случайный секрет не короче 32 символов. Значения с пробелами в `EnvironmentFile` оформляйте по синтаксису systemd. Не храните этот файл в Git, артефактах CI или переменных `VITE_*`.
4. Проверьте `APP_URL`: HTTPS, точный публичный origin, без токенов и query-параметров. `TRUST_PROXY_HOPS=1` допустим только когда Node доступен исключительно через один доверенный reverse proxy. Закройте внутренний порт межсетевым экраном.
5. Настройте в почтовом сервисе свой домен отправителя, SPF/DKIM и доставку. Проверьте реальное подтверждение почты и восстановление пароля, включая одноразовость ссылок. Журнал разработки нельзя использовать для production-писем.
6. Шаблоны `deploy/japanese.service` и `deploy/Caddyfile` описывают запуск непривилегированного сервиса и TLS reverse proxy. Уточните путь к npm для своего сервера, `WorkingDirectory`, `APP_DOMAIN` и настройки DNS. `APP_DOMAIN` задаётся в окружении процесса Caddy, а не Node-приложения. Шаблоны не являются свидетельством уже выполненного развёртывания.
7. Запустите `npm start` под менеджером процессов. Ошибка конфигурации должна приводить к отказу запуска, а не переходу в демонстрационный или небезопасный режим. Первые миграции выполняются до приёма запросов; перед обновлением схемы сделайте резервную копию.

### Контракт окружения

Основной контракт находится в `server/config.ts`; порт, host и чтение `.env` — в `server/index.ts`. Не задавайте новые переменные наугад: неизвестный ключ не является поддержанной настройкой.

| Переменные                                                      | Требование                                                                                                                                                           |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                                                      | `development`, `test` или `production`; `npm start` явно выбирает production                                                                                         |
| `APP_URL`                                                       | В production обязателен публичный HTTPS-origin; используется для аутентификации и ссылок, без учётных данных, query и fragment                                       |
| `HOST`, `PORT`                                                  | Шаблон слушает `127.0.0.1:3000`; `PORT` — 1–65535. Аргументы `--host`/`--port` имеют приоритет                                                                       |
| `TRUST_PROXY_HOPS`                                              | Целое число 0–2; по умолчанию 0. Значение должно соответствовать закрытому реальному пути reverse proxy                                                              |
| `APP_DATA_DIR`, `DATABASE_PATH`                                 | Приватный каталог и путь к постоянному локальному SQLite-файлу; явный `DATABASE_PATH` обязателен в production, in-memory не допускается                              |
| `BETTER_AUTH_SECRET`                                            | Отдельный высокоэнтропийный секрет минимум 32 символа, без пробелов; не копируйте development-секрет                                                                 |
| `OPERATOR_NAME`, `OPERATOR_EMAIL`, `OPERATOR_ADDRESS`           | Реальные непустые реквизиты и корректный email обязательны в production; эти данные публичны в информации об операторе                                               |
| `TERMS_VERSION`, `TERMS_URL`                                    | **Оба обязательны явно в production**, без даты или URL по умолчанию. URL — HTTPS без credentials; версия и адрес должны указывать на юридически проверенные условия |
| `RESEND_API_KEY`, `RESEND_FROM`                                 | Оба обязательны в production; отправитель — email либо `Имя <email>`, настроенный у провайдера                                                                       |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_ID` | Либо все отсутствуют и оплата отключена, либо все заданы и валидны; production принимает только live-режим                                                           |

Согласие при регистрации сохраняет `TERMS_VERSION`, `TERMS_URL` и время принятия. Переменные не редактируют автоматически текст страниц `/legal/terms` и `/legal/privacy`. Сверьте отображаемую редакцию с конфигурацией до запуска; при изменении условий заранее определите юридический порядок уведомления и повторного согласия — наличия новой строки env для этого недостаточно.

`AUTH_SECRET` и `DATABASE_URL` принимаются как резервные имена, если основных переменных нет. Используйте документированные `BETTER_AUTH_SECRET` и `DATABASE_PATH`, не дублируйте их: `DATABASE_URL` здесь означает путь SQLite, а не адрес PostgreSQL или другого сервера.

## Платежи

- Создайте ровно один активный Price: **2000 центов, USD, recurring/month, interval_count=1**. Сервер проверяет эти параметры, клиент не выбирает цену или customer ID.
- Укажите `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` и `STRIPE_PRICE_ID`. Частичная настройка — ошибка. Проверка Price выполняется при старте: недоступный провайдер или неподходящая цена блокируют запуск с включённой оплатой. Без всех трёх настроек оформление недоступно; фиктивная подписка не выдаётся.
- Настройте Customer Portal: просмотр счетов, смена карты, отмена следующего продления. Не включайте смену на произвольные тарифы, которые приложение не поддерживает.
- Webhook: `POST /api/billing/webhook`. Настройте как минимум `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated` и `customer.subscription.deleted`. `server/billing.ts` получает ID подписки из события и запрашивает её актуальное состояние у провайдера. Тело принимается без предварительного преобразования для проверки подписи; успешная обработка запоминается по ID события. Повторные доставки не должны дублировать доступ.
- Подтверждение доступа приходит от провайдера, а не из `?checkout=success`. Не выдавайте доступ вручную по скриншоту платежа.
- До реальных продаж проверьте тестовую оплату, повторную доставку, перестановку событий, отмену, завершение периода, неуспешное продление и восстановление оплаты в отдельной development/test-среде. `NODE_ENV=production` с test-ключом намеренно не запускается; не ослабляйте эту проверку ради испытаний. После тестов отдельно проверьте настройку live-аккаунта, webhook и портала. Тесты с подменённым транспортом проверяют нашу логику, но не заменяют сценарии настоящего провайдера.
- 7-дневный trial начинается при создании аккаунта, не собирает карту и не запускает автосписание. Это trial нашего хранения, не автоматическая платная подписка Stripe. После окончания доступа сохранённые записи доступны для чтения, экспорта, удаления и сброса; **новые учебные серверные сохранения** требуют действующего trial или подписки. Все материалы остаются читаемыми, а бесплатный гостевой режим — локальным.
- Определите применимые налоги, правила возвратов и обязательные уведомления до продаж. Наличие цены в коде и ссылки на Checkout само по себе не настраивает налоговый учёт, поддержку возвратов или юридически корректное оформление подписки.

Справка провайдера: [события подписок и webhook](https://docs.stripe.com/billing/subscriptions/webhooks), [настройка Customer Portal](https://docs.stripe.com/customer-management/integrate-customer-portal). Проверяйте отдельно sandbox/test и live-конфигурацию.

## Синхронизация и жизненный цикл данных

`GET /api/learning` читает записи владельца, `PUT /api/learning` принимает `{ state, revision }`. Сохранение выполняется в транзакции; устаревшая ревизия возвращает `409 REVISION_CONFLICT` и текущую серверную версию. Это защита от незаметной перезаписи, не автоматическое слияние. Сервер заново разбирает учебное состояние и пересчитывает результаты, но не превращает пользовательскую самопроверку в независимую аттестацию.

В гостевом режиме запись идёт только в `localStorage`. Вход не отправляет гостевые данные автоматически: перенос в `/account` требует явного подтверждения замены, и для записи необходим действующий доступ. При потере сети аккаунтные изменения остаются в памяти вкладки, а не в постоянной offline-очереди. В поддержке сначала предложите экспортировать эти изменения и только потом выбирать серверную версию или перезагружать страницу.

`/progress` экспортирует и импортирует учебный JSON; `/account` скачивает полный архив через `GET /api/account/export`. Это разные форматы: архив аккаунта не предназначен для обратного импорта как прогресс. Экспорт, чтение и удаление не должны зависеть от продления подписки. Сброс учебного прогресса не удаляет аккаунт, согласие или обращения и не начинает новый trial.

Удаление аккаунта удаляет рабочие записи по связям БД и отзываемые сессии. Оно заблокировано, пока у провайдера есть действующая или неоплаченная подписка, либо её состояние невозможно проверить; сначала требуется урегулировать оплату. Это не причина требовать новую подписку для удаления. Оператор отдельно определяет срок хранения резервных копий, уничтожение данных в них и работу с обязательными платёжными записями провайдера.

## Резервное копирование и восстановление

База содержит персональные данные. Снимки должны иметь ограниченные права и шифроваться при переносе во внешнее хранилище. Не прикладывайте их к PR, обращениям или публичным логам.

Команды CLI выполняйте из каталога приложения от сервисного пользователя. `EnvironmentFile` systemd **не экспортируется в ваш shell**: задайте путь явно, чтобы не скопировать случайно development-базу. Для локальной разработки уберите этот `export`; тогда используются `.env` или `server/data/`.

```sh
export DATABASE_PATH=/var/lib/japanese/university-in-a-box.sqlite

# Копия указанной базы, включая согласованное состояние WAL.
npm run ops -- backup --to /var/lib/japanese/backups/2026-09-06.sqlite

# Восстановление ВСЕГДА создаёт новый файл и не перезаписывает текущий.
npm run ops -- restore --from /var/lib/japanese/backups/2026-09-06.sqlite \
  --to /var/lib/japanese/restored.sqlite
```

Используется SQLite backup API, а не копирование только основного файла поверх активного WAL. Проверяются целостность и внешние ключи. Уже существующий destination отклоняется; файлы создаются с правами `0600`. Проверка round-trip входит в тесты.

Для реального восстановления остановите сервис, укажите новый `DATABASE_PATH`, запустите и проверьте вход, последнюю попытку, черновик и состояние подписки. Старую базу сохраните закрытой до окончания проверки. Восстановление старого снимка может вернуть сессии и устаревшее состояние подписок: отзовите восстановленные сессии и сверьте платежи с провайдером перед открытием доступа.

Оператор должен назначить автоматическое расписание, шифрованную внешнюю копию, срок хранения и регулярную тренировку восстановления. Автоматическое off-site копирование в этом репозитории **не настроено**. Тест локального восстановления не подтверждает наличие внешних копий.

## Поддержка

Пользователь создаёт обращение в `/help` и видит его статус и ответ. Оператор работает с той же базой через защищённый доступ к серверу, без общедоступной административной панели:

```sh
export DATABASE_PATH=/var/lib/japanese/university-in-a-box.sqlite
npm run ops -- support-list
npm run ops -- support-read --id TICKET_ID --to /private/ticket.json
npm run ops -- support-reply --id TICKET_ID --file /private/reply.txt
```

`/private/` здесь обозначает подготовленный оператором закрытый каталог, доступный сервисному пользователю, а не путь, создаваемый приложением. `support-list` выводит до 100 последних обращений, но не печатает почту и текст. Полный текст читается в отдельный **новый** файл с правами `0600`. Ответ из файла должен содержать 1–5000 символов после обрезки внешних пробелов; он сохраняется как `reply` с временем `repliedAt` в API (`replied_at` в БД), появляется у владельца аккаунта, а обращение получает статус «Закрыто». Ответ входит в полный экспорт аккаунта. CLI не отправляет уведомление по почте и не реализует очередь работы команды поддержки.

Не обещайте срок ответа, пока не назначены люди и график поддержки. Ошибки учебного материала передавайте в предметную редактуру, а не исправляйте ключи старых задач незаметно.

## Наблюдение и инциденты

Следите за доступностью API, ошибками 5xx, свободным диском, успешностью резервных копий, доставкой писем и недоставленными webhook в кабинете провайдера. Не включайте логирование тел запросов, Cookie, Authorization, ссылок восстановления или содержимого письменных работ. По умолчанию приложение не добавляет рекламную аналитику.

При утечке секрета: ограничьте доступ, отзовите ключи у провайдера, замените секреты и сессии, проверьте целостность базы и журнал платёжных событий. Следуйте применимым требованиям уведомления пользователей и регулятора; конкретную юрисдикцию и ответственного должен определить оператор до запуска.

## Критерии публичного запуска

- [ ] Реальный оператор, применимая юрисдикция и юридически проверенные условия/политика; в документах нет незаполненных обязательных реквизитов.
- [ ] Независимая предметная проверка всех уроков, ключей, переводов и письменных рубрик; результаты проверки зафиксированы по редакциям.
- [ ] Проверены лицензии и атрибуция конкретных используемых материалов; отсутствуют NC/ND, закрытые тексты и запрещённые медиа.
- [ ] Реальные DNS/TLS, постоянный диск, изолированная production-база, секреты вне Git и отработанное восстановление.
- [ ] Реальные почтовые сценарии и полный платёжный цикл проверены отдельно от подмен транспортов в тестах.
- [ ] Проверен серверный запрет всех новых учебных сохранений после trial, включая черновики и карточки; чтение материалов, экспорт, удаление и сброс остаются доступны без продления.
